## 1. ארכיטקטורה בקצרה

```
עובד בשטח ──► קבוצת וואטסאפ ──► בוט Grok ──► Drive (גיבוי, ללא שינוי)
                                     │
                                     └─► POST /api/webhook/whatsapp  (חתום HMAC)
                                              │
                                              ├─ שמירה גולמית: raw_messages + תמונה ל־Storage   (מיד, מחזיר 200)
                                              └─ after(): עיבוד ─► Claude מחלץ שדות ─► entries
                                                                    └─ חסר מידע ─► status = 'review'
מנהל פרויקט ──► אתר Next.js (Vercel) ──► Supabase (RLS לפי פרויקט)
```

**עקרונות:**
- **קודם שומרים, אחר כך מעבדים.** ההודעה הגולמית נשמרת תמיד, גם אם ה־AI נופל. אפשר לעבד מחדש.
- **הודעה אחת = בקשה אחת.** בוואטסאפ כל תמונה היא הודעה נפרדת, לכן כל בקשה מכילה טקסט ועד קובץ מדיה אחד. זה גם שומר מתחת למגבלת 4.5MB של Vercel.
- **קיבוץ הודעות:** עובד שולח לרוב כמה תמונות ואז טקסט (או להפך). הודעות מאותו שולח בתוך חלון זמן (ברירת מחדל 15 דק') מתקבצות לרישום אחד ביומן.
- **הרשאות במסד הנתונים (RLS)**, לא רק במסך.

## 3. מבנה מסד הנתונים (Supabase / Postgres)

```sql
-- משתמשים (הרחבה של auth.users)
create table profiles (
  id          uuid primary key references auth.users on delete cascade,
  username    text unique not null,
  full_name   text not null,
  role        text not null default 'manager' check (role in ('admin','manager')),
  active      boolean not null default true,
  created_at  timestamptz not null default now()
);

-- פרויקטים
create table projects (
  id          uuid primary key default gen_random_uuid(),
  name        text unique not null,              -- "כביש 334"
  aliases     text[] not null default '{}',      -- {"334","כביש334","ציר 334"} — עוזר ל-AI לשייך
  lat         double precision,                  -- למזג אוויר
  lng         double precision,
  active      boolean not null default true,
  created_at  timestamptz not null default now()
);

-- שיוך מנהלים לפרויקטים
create table project_managers (
  project_id  uuid references projects on delete cascade,
  user_id     uuid references profiles on delete cascade,
  primary key (project_id, user_id)
);

-- רשימת סוגי עבודה קבועה (לסינון אחיד)
create table work_types (
  name        text primary key                   -- חפירה, מילוי, ניקוז, הידוק, ...
);

-- כל הודעה שהבוט שלח, כמו שהיא
create table raw_messages (
  id            uuid primary key default gen_random_uuid(),
  wa_message_id text unique not null,            -- מונע כפילויות
  group_id      text,
  sender_name   text,
  sender_phone  text,
  sent_at       timestamptz not null,
  text          text,                            -- יכול להיות ריק
  media_path    text,                            -- נתיב ב-Storage, אם יש תמונה
  payload       jsonb not null,                  -- הבקשה המקורית (בלי הקובץ)
  status        text not null default 'received'
                check (status in ('received','processed','failed','ignored')),
  error         text,
  entry_id      uuid,                            -- לאיזה רישום שויכה
  received_at   timestamptz not null default now()
);

-- רישום ביומן (אחד או יותר לכל הודעה/קבוצת הודעות)
create table entries (
  id             uuid primary key default gen_random_uuid(),
  project_id     uuid references projects,        -- null = לא שויך → לבדיקה
  entry_date     date not null,
  entry_time     time,
  location       text,                            -- "חתך 45" / "ק"מ 2+300"
  work_types     text[] not null default '{}',
  workers        text[] not null default '{}',
  equipment      text[] not null default '{}',    -- "באגר 30 טון", "מכבש"
  weather        text,
  reporter_name  text,
  original_text  text,                            -- הטקסט מהוואטסאפ כמו שהוא
  notes          text,                            -- תיקון/הערה של מנהל
  status         text not null default 'ok' check (status in ('ok','review')),
  review_reason  text,                            -- "פרויקט לא ברור", "אין טקסט"...
  ai_model       text,
  ai_raw         jsonb,                           -- מה ה-AI החזיר (לדיבוג)
  approved_by    uuid references profiles,
  approved_at    timestamptz,
  created_at     timestamptz not null default now(),
  updated_at     timestamptz not null default now(),
  search         tsvector generated always as (
                   to_tsvector('simple', coalesce(original_text,'') || ' ' ||
                   coalesce(location,'') || ' ' || coalesce(notes,''))) stored
);

create table entry_photos (
  id            uuid primary key default gen_random_uuid(),
  entry_id      uuid not null references entries on delete cascade,
  raw_message_id uuid references raw_messages,
  storage_path  text not null,                    -- bucket "photos" (פרטי)
  taken_at      timestamptz,
  created_at    timestamptz not null default now()
);

-- אינדקסים לחיפוש
create index on entries (project_id, entry_date desc);
create index on entries using gin (work_types);
create index on entries using gin (workers);
create index on entries using gin (equipment);
create index on entries using gin (search);
create index on entries (status) where status = 'review';
```

**הרשאות (RLS):**
- פונקציית עזר `is_admin()` ו־`my_projects()` (security definer).
- `entries`, `entry_photos`: קריאה אם `is_admin()` או `project_id in my_projects()`. עדכון (תיקון/אישור) — אותו תנאי.
- רישומים בלי פרויקט (`project_id is null`) — רק מנהל מערכת רואה ומשייך.
- `projects`: מנהל רואה רק את שלו; יצירה/עריכה רק admin.
- `profiles`, `project_managers`: רק admin עורך; כל משתמש רואה את עצמו.
- `raw_messages`: רק admin (ודרך השרת עם service_role).
- Storage bucket `photos` פרטי; התמונות מוצגות דרך Signed URLs שנוצרים בשרת רק אחרי בדיקת הרשאה.
- ה־Webhook כותב עם `service_role` — רק בשרת.

## 4. ה־Webhook וחילוץ השדות

**בקשה מהבוט** — `POST /api/webhook/whatsapp`, `multipart/form-data`:
| שדה | תוכן |
|---|---|
| `meta` | JSON: `wa_message_id, group_id, sender_name, sender_phone, sent_at (ISO), text, reply_to?` |
| `file` | תמונה (אופציונלי, אחת לכל היותר) |
| כותרות | `X-Timestamp`, `X-Signature = HMAC-SHA256(WEBHOOK_SECRET, timestamp + "." + sha256(body))` |

**השרת:**
1. בודק חתימה + שהזמן בטווח 5 דק' (נגד שליחה חוזרת) → אחרת 401.
2. בודק גודל (תמונה עד 10MB, טקסט עד 20,000 תווים — ארוך יותר נחתך ומסומן).
3. `wa_message_id` כבר קיים → מחזיר 200 `duplicate` בלי לעשות כלום.
4. שומר תמונה ל־Storage ושורה ב־`raw_messages` → מחזיר 200.
5. ב־`after()` (ממשיך אחרי התשובה): קיבוץ + Claude + יצירת/עדכון `entries`.

**קיבוץ:**
- תמונה בלי טקסט → מצטרפת לרישום הפתוח האחרון של אותו שולח בחלון 15 דק'. אין כזה → רישום חדש "לבדיקה: תמונה בלי טקסט", ואם יגיע טקסט בחלון — יתמזגו.
- טקסט → נשלח ל־Claude יחד עם תמונות מהחלון (Claude רואה גם את התמונות — עוזר לזהות כלים ועבודה).

**Claude:** מקבל את הטקסט, שם השולח, התאריך, רשימת הפרויקטים + כינויים, ורשימת סוגי העבודה. מחזיר JSON מובנה (tool use / structured output):
`project_id | null, confidence, entry_date, location, work_types[], workers[], equipment[], weather | null, split[]` — הודעה אחת שמתארת שני פרויקטים מתפצלת לשני רישומים.
- `project_id = null` או confidence נמוך → `status = 'review'` עם סיבה.
- התאריך: ברירת מחדל = תאריך השליחה. אם העובד כתב "אתמול" / תאריך — לפי הטקסט.
- שגיאת API → `raw_messages.status = 'failed'`, כפתור "עבד מחדש" בניהול.

**מזג אוויר:** אם כתוב בהודעה — משם. אחרת אוטומטית מ־Open-Meteo (חינמי, בלי מפתח) לפי מיקום הפרויקט ותאריך (טמפ' מקס/מינ', גשם, רוח). ← *ממתין לאישור, שאלה 2.*

## 5. ה־Hook לתיעוד (`docs/יומן-פיתוח.md`)

`.claude/settings.json`:
```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          { "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/dev-log.mjs\"", "timeout": 15 }
        ]
      }
    ]
  }
}
```

`.claude/hooks/dev-log.mjs` (רץ בסוף כל תשובה של Claude Code):
1. קורא מ־stdin את ה־JSON של ה־Hook (כולל `transcript_path`).
2. רשימת קבצים שהשתנו: `git status --porcelain` (בלי `docs/יומן-פיתוח.md` עצמו).
3. אם הרשימה זהה לרישום הקודם (נשמר hash ב־`.claude/hooks/.last-log`, ב־gitignore) או ריקה — יוצא בלי לכתוב (כדי לא להציף בשורות ריקות).
4. "מה בוצע" = שורת הסיכום מההודעה האחרונה של Claude ב־transcript (עד 300 תווים).
5. מוסיף בסוף הקובץ:
```markdown
### 2026-10-18 16:42
**מה בוצע:** הוספת אימות HMAC ל-webhook
**קבצים:** app/api/webhook/whatsapp/route.ts, lib/webhook/verify.ts, tests/unit/verify.test.ts
```
6. תמיד יוצא עם קוד 0 — Hook שנכשל לא עוצר עבודה.

## 7. שאלות פתוחות (צריך תשובה לפני שלב 0)

1. **הודעות לדוגמה** — אפשר לקבל 15–20 הודעות אמיתיות מהקבוצה (טקסט + תיאור התמונות, או ייצוא צ'אט)? בלי זה אי אפשר לכוון את השיוך לפרויקט.
