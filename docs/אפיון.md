# אפיון פרויקט: יומן עבודה יומי לפי פרויקטים — ע.ל.ת

> הועתק מ־`Downloads\אפיון.pdf` (2026-10-18). תוכנית העבודה: [[תוכנית]].

## 1. שם ומטרה
**שם:** יומן עבודה יומי לפי פרויקטים — ע.ל.ת
**מטרה:** תיעוד יומי מסודר לכל פרויקט (כביש 333, כביש 334, כביש הרוחב ועוד) במקום אחד — עובדים, כלים מכניים, עבודות שבוצעו, תמונות, הערות ומזג אוויר — עם אפשרות לחזור אחורה ולחפש כל ביצוע לפי תאריך.

## 2. משתמשים ומקור המידע
- **מקור הנתונים:** קבוצת וואטסאפ של עובדי החברה.
- **מדווחים:** חלק מעובדי החברה בשטח. שולחים לקבוצה תמונות/תיעוד + הערת טקסט קצרה על מה שבוצע.
- **המערכת:** קולטת את ההודעות, משייכת כל דיווח לפרויקט ולתאריך, ומרכזת ליומן עבודה יומי לכל פרויקט.

## 3. גישה וצפייה
- **מנהל פרויקט:** מתחבר למערכת עם שם משתמש וסיסמה.
  - צופה ביומן היומי של הפרויקטים שלו.
  - חוזר אחורה ומחפש לפי תאריך, פרויקט וסוג ביצוע (לדוגמה: "ניקוז בכביש 334 ב־12.10").
  - רואה את התמונות וההערות המקוריות מהוואטסאפ ליד כל רישום.
- **הרשאות:** מנהל פרויקט רואה רק את הפרויקטים שלו. מנהל המערכת רואה הכול.

## 4. שדות בכל רישום ביומן
- תאריך ושעה
- פרויקט
- מיקום / קטע בפרויקט (חתך, ק"מ)
- סוג עבודה (חפירה, מילוי, ניקוז, הידוק ...)
- עובדים שהיו בשטח
- כלים מכניים שעבדו
- תמונות
- הערת טקסט מקורית מהוואטסאפ
- מזג אוויר
- שם המדווח

**לא כולל:** כמויות (שייכות למערכת הרכש).

## 5. קליטת נתונים
- **הזרימה הקיימת נשארת:** עובדים שולחים לקבוצת הוואטסאפ → הבוט (Grok) קולט → נשמר בדרייב.
- **תוספת (Webhook):** כל הודעה שנקלטת נשלחת גם למערכת:
  1. הבוט מעביר את ההודעה (טקסט, תמונות, שולח, שעה).
  2. AI מחלץ את השדות מסעיף 4 ומשייך לפרויקט ולתאריך.
  3. הרישום נשמר במסד הנתונים, התמונות נשמרות באחסון עם קישור לרישום.
  4. אם חסר מידע (למשל פרויקט לא ברור) — הרישום מסומן "לבדיקה" ולא נזרק.
- **הדרייב** ממשיך כגיבוי. **המערכת** היא המקום לצפייה וחיפוש.

## 6. ממשק — אתר רספונסיבי (טלפון + מחשב), עברית מימין לשמאל
1. **התחברות** — שם משתמש וסיסמה.
2. **רשימת פרויקטים** — כל פרויקט עם תאריך הדיווח האחרון.
3. **יומן יומי** — בחירת פרויקט ותאריך → כל הרישומים של היום עם תמונות והערות.
4. **חיפוש וסינון** — תאריך/טווח, פרויקט, סוג עבודה, כלי, עובד, מדווח.
5. **רישומים לבדיקה** — הודעות שה־AI לא הצליח לשייך; המנהל מתקן ומאשר.
6. **ניהול** (מנהל מערכת) — הוספת פרויקטים, משתמשים והרשאות.

## 7. דוחות
- כפתור **"הפק דוח"** במסך היומן: בוחרים פרויקט ותאריך/טווח → PDF מסודר עם רישומים, תמונות, הערות ומזג אוויר.
- אפשר להוריד או לשלוח למזכירה/מפקח.
- אין דוח אוטומטי בגרסה הראשונה.

## 8. כללי עבודה ובדיקות (ייכנסו ל־CLAUDE.md)
- לכתוב קוד מלא לכל שלב, ורק אז להריץ.
- אחרי כל פיצ'ר:
  - בדיקות **E2E** — הזרימה המלאה מהודעת וואטסאפ ועד המסך.
  - בדיקות **Edge** — הודעה בלי טקסט, תמונה בלי פרויקט, הודעה כפולה, הודעה ארוכה מאוד.
  - בדיקות **רגרסיה** — שלא נשבר משהו קיים.
- **אבטחה + Security Review:** הרשאות לפי פרויקט, סיסמאות מוצפנות, אימות שה־Webhook מגיע מהבוט בלבד, מפתחות API רק במשתני סביבה ולא בקוד.
- commit ל־GitHub אחרי כל שלב שעובד.

## 9. טכנולוגיה
- **אתר + שרת:** Next.js
- **מסד נתונים, תמונות והתחברות:** Supabase
- **אחסון האתר:** Vercel (עלייה אוטומטית מ־GitHub)
- **חיבור מהבוט:** Webhook מהבוט הקיים
- **חילוץ שדות:** Grok (כמו בבוט הקיים) או Claude API
- **PDF:** נוצר בשרת בלחיצה על "הפק דוח"
